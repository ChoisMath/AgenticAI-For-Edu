# 좋은 바이브 코딩 프롬프트의 4요소

이 자료는 interactive-visualizer skill이 첫 Artifact 코드를 작성할 때 따를 4요소와 기술적 제약을 정의한다.

바이브 코딩(Vibe Coding)은 교사가 프로그래밍 지식 없이 자연어로 원하는 도구를 설명하면 AI가 작동하는 코드를 만들어 주는 방식이다. 그러나 자연어가 모호하면 결과물도 모호하다. 4요소는 그 모호함을 줄이는 최소 골격이다.

---

## 4요소

### 요소 1. 무엇을 하는 도구인가 (What)

**도구의 핵심 기능을 한 문장으로 정의**한다.

#### 좋은 정의의 조건
- **동사로 시작** — "보여 준다", "비교한다", "조작한다" 같은 능동 동사
- **학습 행위 명시** — 학생이 그 도구로 "무엇을 하는지"가 분명함
- **30자 이내** — 한 문장에 담을 수 있어야 도구의 초점이 분명해짐

#### 예시
- ✓ "학생이 슬라이더로 두 함수를 동시에 조작하며 교차점을 찾는 도구"
- ✓ "분포의 평균과 표준편차를 학생이 슬라이더로 바꾸며 정규분포의 변화를 관찰하는 도구"
- ✗ "지수함수를 가르치기 위한 시각 자료" (무엇을 하는지 불명확)
- ✗ "수학을 재미있게 배우는 도구" (구체성 없음)

#### 점검 질문
- 학생이 "이 도구로 무엇을 하느냐"고 물었을 때, 한 문장으로 답할 수 있는가?

---

### 요소 2. 누가 쓰는가 (Who)

**사용자(학생)의 학년·맥락·기기 환경을 명시**한다.

#### 좋은 정의의 조건
- **학년·과목 명시** — "고2 수학", "중3 과학"처럼 정확히
- **기기 환경 명시** — "학생 개인 휴대폰", "교실 태블릿", "PC 실습실"
- **사용 시점 명시** — "수업 도입 5분", "단원 마무리 30분", "방과 후 자율 탐구"

#### 사용자에 따라 달라지는 것
- 슬라이더의 크기 (휴대폰이면 더 크게)
- 글자 크기 (모바일이면 더 크게)
- 한 화면에 들어가는 정보량 (작은 화면이면 줄임)
- 한국어 어휘 수준 (학년에 맞게)

#### 예시
- ✓ "고2 학생, 자기 휴대폰으로, 수업 도입 10분간"
- ✓ "중3 과학 학생, 교실 PC 실습실, 1차시 35분"
- ✗ "학생" (구체성 없음)
- ✗ "고등학생용" (학년 불명확, 환경 미정)

#### 점검 질문
- 학생의 학년·환경·시점이 한 문장에 들어 있는가?
- 그 정보가 도구 설계의 결정(크기·복잡성·시간)에 반영되는가?

---

### 요소 3. 어떤 입력과 출력이 있는가 (Input/Output)

**학생이 조작할 변수와 도구가 보여 줄 결과를 명시**한다.

#### 입력 (학생이 조작하는 것)
- 슬라이더로 조절하는 변수들 (이름·범위·단위)
- 클릭하는 버튼들 (프리셋, 리셋, 저장)
- 입력하는 텍스트 (탐구 질문 답)

#### 출력 (도구가 보여 주는 것)
- 그래프 (변수 변화에 따라 즉시 갱신)
- 수치 (현재 값, 계산 결과)
- 시각 표시 (마커, 강조, 애니메이션)

#### 좋은 정의의 조건
- **변수 이름과 범위 명시** — `b: 1.1 ~ 3.0 (0.1 단위)`
- **출력의 위치 명시** — "그래프는 중앙, 수치는 그래프 옆"
- **입력에 따른 출력의 반응 명시** — "슬라이더를 움직이면 그래프가 즉시 갱신"

#### 예시 (좋음)

```
입력:
- 지수함수 밑(b): 1.1 ~ 3.0, 0.1 단위
- 일차함수 기울기(m): 1 ~ 100, 1 단위
- x축 범위: 5 ~ 50

출력:
- 좌표평면에 두 함수의 그래프 (지수함수=파랑, 일차함수=주황)
- 두 함수의 교차점 좌표 (그래프 우측에 큰 글씨)
- 교차점 위치에 동그라미 마커 + 처음 화면에 나타날 때 반짝임
```

#### 미통과 신호
- 변수 이름은 있으나 범위가 없음 (학생이 조작 가능한 영역이 모호)
- 출력의 위치가 정해지지 않음 (Mayer의 공간 근접성 원리 위배 위험)

---

### 요소 4. 어떤 학습이 일어나야 하는가 (Learning)

**도구 사용 후 학생의 머릿속에서 일어나야 할 변화를 명시**한다.

이것이 4요소 중 가장 자주 빠지는 부분이다. 그런데 이 요소가 빠지면 도구는 '학습 도구'가 아니라 그저 '예쁜 시뮬레이션'이 된다.

#### 좋은 정의의 조건
- **인지적 변화로 표현** — "이해하게 한다", "구별하게 한다", "체득하게 한다"
- **학생의 직관과 도구의 결과 사이의 충돌 지점 명시**
- **도구 사용 전후의 차이 명시**

#### 예시
- ✓ "학생이 '일차함수 기울기 100이면 절대 안 진다'는 직감으로 출발했다가, 도구로 확인하면서 '결국 지수가 이긴다'는 사실을 체득"
- ✓ "학생이 평균만 보던 시선에서, 슬라이더로 표준편차를 키워 보며 '평균이 같아도 분포가 다르면 의미가 다르다'는 것을 인지"
- ✗ "지수함수를 이해" (구체성 없음, 도구 없이도 가능한 표현)
- ✗ "학생이 재미있게 학습" (학습 결과가 아닌 감상)

#### 점검 질문
- 도구 사용 전 학생의 머릿속과 사용 후 학생의 머릿속에 무엇이 달라지는가?
- 그 변화가 도구 없이는 일어나기 어려운 것인가?

#### 미통과 신호
- 학습 결과가 "이해", "학습", "재미"처럼 모호함
- 도구 없이도 글로 가능한 학습 내용임 (그러면 인터랙티브 도구가 필요 없음)
- 사용 전후의 차이를 학생이 의식할 수 없음

---

## 4요소 점검표

첫 코드 작성 전, 다음 표를 채울 수 있어야 한다. 한 칸이라도 비어 있으면 작성을 시작하지 않는다.

| 요소 | 채울 내용 |
|---|---|
| 1. 무엇을 하는 도구인가 | (한 문장) |
| 2. 누가 쓰는가 | 학년 / 환경 / 시점 |
| 3. 어떤 입력과 출력이 있는가 | 입력 변수와 범위 / 출력 형태와 위치 |
| 4. 어떤 학습이 일어나야 하는가 | (인지적 변화 한 문장) |

이 표가 채워지지 않으면 교사에게 추가 정보를 요청한다.

## 기술적 제약 (필수)

작성하는 모든 Artifact는 다음 제약을 반드시 따른다. 이 제약은 미적 선택이 아니라 학생 사용 환경의 실제 요구사항이다.

### 1. 단일 HTML 파일

- 외부 파일 의존 없이 한 파일 안에 모든 것이 담김
- HTML, CSS, JS가 한 `.html` 파일 안에
- 외부 이미지·CSS·JS 파일 참조 금지

### 2. 브라우저 저장소 미사용 (절대 금지)

- `localStorage` 사용 금지
- `sessionStorage` 사용 금지
- IndexedDB 사용 금지
- Cookie 저장 금지

이유: Claude Artifact 환경에서 위 API들이 작동하지 않는다. 사용하면 도구가 무너진다. 모든 상태는 React state 또는 일반 JavaScript 변수로 관리한다.

### 3. 외부 라이브러리 최소화

- 가능하면 외부 라이브러리 없이 작성
- 그래프는 SVG로 직접 그리기 (Chart.js, D3 등의 의존을 줄임)
- React만 활용 가능 (이미 환경에 있음)
- 만약 라이브러리가 꼭 필요하면 cdnjs.cloudflare.com에서 가져오는 것만 허용

### 4. 한국어 인터페이스

- 모든 라벨, 버튼, 안내문이 한국어
- 영어 변수명이 노출되지 않도록 (예: `Click here` 대신 `여기를 누르세요`)

### 5. 모바일 대응

- 학생이 휴대폰으로 접속할 수 있어야 함
- 슬라이더 손잡이는 최소 44×44 픽셀 (Apple Human Interface Guidelines 권장)
- 글자 크기는 최소 14pt 이상
- 화면 너비에 따라 레이아웃이 자동 조정 (반응형)

### 6. 차분한 색감

- 학습에 집중할 수 있도록 과한 시각적 자극 회피
- 배경은 단색 또는 옅은 그레이 (`#f5f5f5` 정도)
- 핵심 강조 색상은 두세 가지로 제한

### 7. 즉시 작동

- 페이지를 열자마자 학생이 바로 조작 가능해야 함
- 로딩 화면, 회원가입 같은 진입 장벽 없음
- 학생이 5초 안에 첫 슬라이더를 움직일 수 있어야 함

---

## 4요소가 위배되면 일어나는 일

### 요소 1(What)이 모호하면
도구가 무엇을 하는지 학생이 첫 5초에 파악하지 못한다. 학생은 헤매다 흥미를 잃는다.

### 요소 2(Who)가 모호하면
학년·환경에 맞지 않는 도구가 나온다. 휴대폰 접속을 가정하지 않아 슬라이더가 작거나, 학년에 맞지 않는 어휘가 등장한다.

### 요소 3(I/O)이 모호하면
변수 범위가 잘못 설정되어 학생이 조작해도 변화가 안 보이거나, 출력의 위치가 산만하다.

### 요소 4(Learning)가 모호하면
도구가 작동은 하지만 학습이 일어나지 않는다. 슬라이더 조작이 재미는 있지만 머릿속에 남는 것이 없다.

네 요소 중 하나라도 흐릿한 채 작성에 들어가면, 결과물은 다시 만들어야 하는 도구가 된다.
