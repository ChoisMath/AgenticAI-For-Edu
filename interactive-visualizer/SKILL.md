# interactive-visualizer skill

학생이 손으로 조작하며 개념을 체득하는 인터랙티브 학습 도구를 Claude Artifact로 생성한다.

## 핵심 원칙

이 skill은 다음 한 가지 전제 위에 만들어졌다.

> 슬라이드는 교사가 설명하는 도구지만, 인터랙티브 도구는 학생이 탐구하는 도구다.

이 차이가 도구 설계의 모든 결정을 갈라 놓는다. 슬라이드를 잘 만드는 것과 학습 도구를 잘 만드는 것은 완전히 다른 일이다. 이 skill은 슬라이드 제작이 아니라 학습 도구 제작을 위해 만들어졌다.

## 핵심 메시지

> 바이브 코딩의 진짜 능력은 '더 복잡한 도구를 만드는 것'이 아니라 '더 교육적인 도구를 판별하는 것'이다.

이 skill은 교사가 코드를 잘 다루게 하는 것이 목표가 아니다. 교사가 자기 학급에 맞는 학습 도구를 판별하고 다듬는 역량을 키우는 것이 목표다. 첫 코드는 출발점일 뿐, 학생 역할 테스트와 비평가 점검을 거쳐 한 단계씩 다듬어 가는 것이 본 작업이다.

## 입력

교사로부터 다음을 받는다.

- **단원**: 예) "<대수> 지수함수의 활용"
- **학년**: 예) "고2"
- **학습 목표**: 학생이 이 도구를 통해 무엇을 체득하길 바라는가 — 예) "지수함수가 결국 일차함수를 추월한다는 사실을 슬라이더로 직접 확인"
- **학생이 조작할 핵심 변수**: 예) "지수함수 밑(b), 일차함수 기울기(m), x축 범위"
- **(선택) 프리셋 버튼 시나리오**: 예) "초반엔 일차가 앞선다 / 교차 순간 / 지수의 승리"

학습 목표와 핵심 변수가 입력에 없으면 작업을 시작하지 않는다. 교사에게 물어 명확히 한 뒤 진행한다. 핵심 변수가 모호하면 도구가 학생의 사고를 어디로 이끌어야 할지 정해지지 않는다.

## 워크플로우

### 1단계. 작성 기준 로드

다음 두 파일을 읽는다.

- `resources/좋은_바이브코딩_프롬프트의_4요소.md` — 첫 코드 작성의 4요소 + 기술적 제약
- `resources/Mayer_5원리.md` — 멀티미디어 학습의 5가지 원리

### 2단계. 첫 Artifact 코드 작성 + 학생 역할 테스트 시나리오 3개

`좋은_바이브코딩_프롬프트의_4요소.md`의 4요소 — ① 무엇을 하는 도구인가 ② 누가 쓰는가 ③ 어떤 입력과 출력이 있는가 ④ 어떤 학습이 일어나야 하는가 — 를 적용해 단일 HTML 파일의 Artifact를 작성한다.

코드를 출력한 직후, 교사가 학생 역할로 테스트해 볼 **시나리오 3개**를 함께 제시한다. 시나리오는 다음 세 가지를 각각 검증할 수 있도록 설계한다.

- **극단값 시나리오**: 학생이 슬라이더를 끝까지 밀었을 때 도구가 무너지지 않는가
- **교차/변곡 시나리오**: 학습의 핵심 통찰이 일어나는 순간을 제대로 보여 주는가
- **반직관 시나리오**: 학생의 직관과 도구의 결과가 어긋나는 지점이 분명히 드러나는가

### 3단계. 자가 진단

코드를 한 번 더 보고 다음 형식으로 자가 진단표를 출력한다.

```
[자가 진단표]

1. 4요소의 구현 — ✓ 통과 / △ 확인 필요 / ✗ 미통과
   ① 도구 목적 명확: ...
   ② 사용자(학생) 명확: ...
   ③ 입력·출력 명확: ...
   ④ 학습 결과 명확: ...

2. 기술적 제약 — ✓ 통과 / △ 확인 필요 / ✗ 미통과
   - 단일 HTML 파일: ✓
   - localStorage/sessionStorage 미사용: ✓
   - 외부 라이브러리 최소화: ...
   - 한국어·모바일 대응: ...

3. 학생 시나리오 3개 제시 — ✓ 통과 / △ 확인 필요 / ✗ 미통과
   (시나리오 종류 명시)
```

자가 진단에서 모든 항목이 ✓이라면 교사에게 그대로 전달한다. △ 또는 ✗가 있다면 보완 후 다시 작성한다.

### 4단계. UI/UX 개선 (교사 요청 시)

교사가 학생 역할로 테스트한 뒤 발견한 문제를 자연어로 전달하면 그에 맞춰 코드를 수정한다.

흔한 요청 예:
- "슬라이더가 너무 작아서 손가락으로 누르기 어렵다"
- "현재 값을 슬라이더 옆에 큰 글씨로 함께 표시해 줘"
- "교차점이 화면에 나타나는 순간 마커가 짧게 반짝이게 해 줘"

수정 후 변경된 부분을 한 줄로 안내하고 다시 한 번 학생 역할로 테스트해 보기를 권한다.

### 5단계. 교육적 스캐폴드 추가 (교사 요청 시)

기능이 작동해도 '게임'에 그치지 않으려면 학습 스캐폴드가 필요하다. 교사가 다음 같은 요청을 하면 도구 안에 사고 유도 장치를 심는다.

- 탐구 질문 N개와 학생이 답을 입력할 텍스트 박스
- '내 실험 결과 저장' 버튼 — 누르면 현재 파라미터·관찰 결과·학생 답이 한 장의 카드로 정리됨
- 단계별 안내 (1단계: ~를 해 보세요, 2단계: ~)

스캐폴드 추가 시에도 4요소 중 ④ "어떤 학습이 일어나야 하는가"를 다시 점검한다.

### 6단계. 비평가 모드 전환 (교사 요청 시)

교사가 다음과 같이 말하면 비평가 모드로 전환한다.

- "지금부터 비평가 역할로 전환해 줘"
- "비평가의 시각으로 점검해 줘"
- "subagents/비평가.md의 기준으로 검토해 줘"

이때는 `subagents/비평가.md`를 읽고 그 안에 정의된 비평가의 자세와 **Mayer 5원리 + 교육적 스캐폴드 5항목 = 10항목**으로 점검한다. 검토가 끝나면 다음 한 줄로 마친다.

> "이상으로 비평을 마친다. 작가 역할로 돌아간다."

### 7단계. 수정 (교사 요청 시)

교사가 "권고대로 수정해 줘"라고 요청하면 작가 모드로 돌아와 비평가의 권고를 반영한 수정본을 작성한다.

## 출력 형식

각 작성마다 다음 두 가지를 함께 출력한다.

1. **Artifact 코드** — 단일 HTML 파일, 즉시 작동
2. **학생 역할 테스트 시나리오 3개** — 교사가 직접 만져 볼 수 있는 구체적 단계

자가 진단표는 코드와 시나리오 다음에 배치한다.

## 회피 사항

이 skill은 다음을 하지 않는다.

- 학생이 읽고 사고하는 텍스트 자료 만들기 (reading-material skill의 영역)
- 학생이 종이에 답을 적는 활동지 만들기 (activity-sheet skill의 영역)
- 의사결정 사례 만들기 (case-based-problem skill의 영역)
- 자료의 사실 확인 (material-validator skill의 영역)
- 발표용 슬라이드 자료 만들기 — 슬라이드는 교사 설명용이며, 본 skill의 목적과 다르다

이 skill은 오직 "학생이 손으로 변수를 바꾸며 개념을 체득하는 인터랙티브 도구"만을 만든다.

## 기술적 제약 (중요)

작성하는 모든 Artifact는 다음을 반드시 따른다.

- **단일 HTML 파일** — 외부 파일 의존 없음
- **localStorage·sessionStorage 사용 금지** — Claude Artifact 환경에서 작동하지 않음. 화면 상태로만 관리
- **외부 라이브러리 최소화** — 추가 라이브러리 없이 가능하면 SVG로 직접 그래프를 그림
- **한국어 인터페이스** — 라벨·버튼·안내가 모두 한국어
- **모바일 대응** — 학생이 휴대폰으로 접속할 수 있어야 함. 슬라이더는 손가락으로 조작 가능한 크기
- **차분한 색감** — 학습에 집중할 수 있도록 과한 시각적 자극 회피

이 제약은 미적 선택이 아니라 학생 사용 환경의 실제 요구사항이다. 어느 하나라도 어기면 학생 앞에서 도구가 작동하지 않는 사태가 일어날 수 있다.

## 작성 예시 (참고)

다음은 한 호출의 입력과 그에 대한 출력의 골격이다.

**입력**:
- 단원: <대수> 지수함수의 활용
- 학년: 고2
- 학습 목표: 지수함수가 결국 일차함수를 추월한다는 사실을 슬라이더로 직접 확인
- 핵심 변수: 지수함수 밑(b: 1.1~3.0), 초기값(a), 일차함수 기울기(m: 1~100), y절편(c), x축 범위
- 프리셋: 초반엔 일차가 앞선다 / 교차 순간 / 지수의 승리(m=100)

**출력의 골격**:

1. **Artifact 코드**
   - 좌측에 슬라이더 5개 (b, a, m, c, x 범위) — 큼직하게
   - 중앙에 좌표평면 — 지수함수(파랑)와 일차함수(주황) 동시 표시
   - 교차점 마커 (반짝임 애니메이션)
   - 우측 상단에 현재 교차점 좌표 (그래프 옆 배치 — 공간 근접성)
   - 프리셋 버튼 3개

2. **학생 역할 테스트 시나리오 3개**
   - 극단값: m=100, b=1.1로 두고 x 범위를 0~5에서 0~50까지 늘려 본다
   - 교차/변곡: '교차 순간' 프리셋을 누르고 교차점이 어디에 나타나는지 본다
   - 반직관: '지수의 승리' 프리셋을 누르고, 학생이 "기울기 100짜리 일차가 절대 안 질 것"이라 직감했을 때와 다른 결과가 나오는지 본다

3. **자가 진단표**
   - 4요소 구현, 기술 제약, 시나리오 3개 — 각각 통과 여부 표시

이 골격은 강제 형식이 아니다. 단원과 학습 목표에 따라 자유롭게 변형 가능하되, 출력 두 가지(코드 + 시나리오 3개)와 자가 진단표는 항상 함께 나간다.
